What is DDD Dropbox?ProgressBuild plan

Messages can wait. People don’t have to.

A stationary stop
for moving messages.

DDD uses mobile transports—such as a bus driver’s phone—to carry encrypted bundles between disconnected clients and an internet-connected server. A drop box lets the client and the transport visit at different times.

New to DDD? Click dotted terms for a short definition and a practical example.

1 / Leave a bundle

A client leaves encrypted bundles at the drop box, then goes. The drop box keeps them ready for a later transport visit.

Illustration of the flow as built on the prototype branch, not live network status. Direct client ↔ transport exchange remains available.

01

One familiar peer for the client.

The client sees another DDD transport. It can leave data at the drop box and still exchange that data with a moving transport later. The drop box can hold many bundles for many clients; it does not need to know which application produced their contents.

02

An explicit relay for the network.

The server knows this node is a dropbox: it registers its own endpoint and TLS identity through control ADUs. Clients record the dropbox in routing.metadata and its inventories list whose bundles it holds, so the server can send replies through any carrier that visits it.

A carrier accepting a bundle completes a local handoff. It does not mean the server—or the destination client—has received it yet.

03

The same encrypted bundle, another hop.

Relayed user bundles keep their original encrypted IDs and bytes. Separately, the dropbox creates and decrypts its own control bundles: inventory reports and recency requests go up; retention plans and recency grants come back. User encryption endpoints stay unchanged.

Wi-Fi Direct first

Two jobs.
One controlled radio cycle.

The Dropbox alternates on two configurable timers: serve clients, then search for and exchange with transports. Phones keep their existing connection behavior; transports keep hosting.

  1. Host clients
  2. Drain & join
  3. Exchange
  4. Restore hosting

Start each timer when its mode is ready. On expiry, close new admissions and finish active work within a fixed cap before switching. Built defaults: 60 s clients, 30 s transports, 15 s cap. Timer rules & tests · Prototype playground. Group model · Interface concurrency · Asynchronous APIs

Wi-Fi Aware is a later link adapter. Inventory, storage, receipts and routing should remain reusable.

How the dropbox works

The dropbox stores other clients’ encrypted bundles and creates its own control bundles. It reaches the server through passing transports.

  1. Forward queued bundles

    Upload every bundle not yet given to this carrier, its own control bundle first, including on the first visit. Sending never waits for the server.

  2. Report what it holds

    The dropbox’s own endpoint sends inventory reports listing the bundles it holds. Client acknowledgements travel inside the clients’ own encrypted bundles, so only the server reads them.

  3. Follow server keep/delete instructions

    The server combines upstream receipts, client acknowledgements and the dropbox’s inventories into a retention plan. The dropbox keeps every copy until a plan lists it.

Routing and control ADUsKeep/delete rulesClient pickup and acknowledgements

Periodic switching is the initial radio design. Discovery finds carriers during transport mode; switching early on a discovery event is optional later work. See the timer and role cycle for behavior and tests.

Built, with a deferred follow-up

Many bundles, simple queue rules

The dropbox uploads everything not yet forwarded and downloads everything a carrier holds; server retention plans clean up. A server-issued pickup list is deferred until visit-cost data exists.

Architectural direction; tests in shared contracts and client visit recording/end-to-end verification

Encryption endpoints stay the same

Reuse client/server encryption and private pickup. The dropbox never receives user-client decryption keys or alters relayed ciphertext. It owns keys only for its own control endpoint. routing.metadata is protected inside endpoint-authored bundles; it is not a mutable relay header.

Keep these decisions in view
  • The Dropbox switches Wi-Fi roles on timers (60 s clients, 30 s transports, 15 s drain cap); transports keep hosting.
  • Forward every queued upstream bundle, own control bundle first, without waiting for the server.
  • Only a server retention plan deletes a relayed copy.
  • The Dropbox serves its own server-issued recency blob under a stable ID; it never re-serves a blob from a carrier.
  • The server owns routing: routing_edge rows from uploads, client routing.metadata and dropbox inventories.

How to use the Progress tracker

The loop

The prototype on ddd_dropbox_prototype works, but it is not going into main as one push. It has been cut into 73 cards in 18 paths. Each card is one reviewed PR.

  1. 1FindPick a path, or any card marked Ready to claim.
  2. 2ClaimWrite your name in the Sheet: on a path row to own the path, or on one card.
  3. 3BuildOpen the card and follow its steps. Its files link to the prototype as a reference.
  4. 4ShipOpen one PR for the card. Paste its link in the Sheet and set In review.
  5. 5UnlockSet Done when it merges. Cards that needed it turn Ready.

Then pick the next card. Finish one path and move to another.

Rules of the road

  • Rebuild, don't cherry-pick. Use the branch to read how it was done, then write it again with review.
  • Merging to main deploys the server. Every server card has to be safe on its own. Read its Deploy safety line before merging.
  • bundle-core first. After changing bundle-core, run mvn install before building the Android apps.
  • Open questions are yours. If a card lists questions, you decide them. Write the decision in notes or a short doc. Better or simpler ideas are welcome.
  • Which apps you touch is a judgement call. Routing and bug-report work is expected to change BundleClient. Say so in the PR.
  • Nothing in the Sheet is secret. Its published copy is public, so keep keys and passwords out of it.
